# TapoControl

A macOS menu bar app for your two Tapo L530 bulbs. It talks to them directly over your home
network with TP-Link's KLAP protocol, so it doesn't need the cloud, Home Assistant or the Jarvis server.

The popover has a Room toggle, scenes (Bright, Warm, Dim, Off), and per-bulb power, brightness,
white temperature and colour. The menu bar icon fills in when any bulb is on.

## First run

1. **Check the bulbs from Terminal first** (optional, but it isolates protocol problems from app problems):
   ```
   cd ~/Desktop/Projects/TapoControl
   python3 tools/klap_probe.py
   ```
   Enter your Tapo email and password when asked. Each bulb should print `KLAP v2 handshake OK` (or `v1`)
   plus its model and state. If one prints `handshake1 HTTP 403`, open the Tapo app → Me → Third-Party
   Services and turn Third-Party Compatibility off and on, with your phone on the same Wi-Fi.
2. Open `TapoControl.xcodeproj` in Xcode.
3. Run the tests with **⌘U**. They check the KLAP crypto byte for byte against python-kasa 0.12.0.
4. Select the **TapoControl** scheme and **My Mac**, then press **⌘R**. If Xcode asks about signing,
   pick your team (MM79KUFN38) under Signing & Capabilities.
5. Click the lightbulb in the menu bar and enter your Tapo email and password. When macOS asks for
   **Local Network** access, click Allow. The app keeps only a derived key, never the password.
6. Optional: Settings → Launch at login.

To keep it installed without Xcode running, use Product → Archive → Distribute App → Custom → Copy App,
then move `TapoControl.app` to `/Applications` and launch it once.

## Troubleshooting

| What you see | What to do |
| --- | --- |
| "Can't reach 192.168.2.x" | Check the bulb has power and the IP is right (Settings in the popover). Check System Settings → Privacy & Security → Local Network → TapoControl is on. |
| "The bulb refused the local login (HTTP 403)" | A firmware update probably switched it back to TPAP. Re-toggle Third-Party Compatibility in the Tapo app. |
| "The bulb rejected the Tapo email or password" | Settings → Change login. The app stops trying after one rejection so it can't lock the bulb. |
| "Login stored in: App container file" | The keychain refused the item under your signing setup, so the key is in a 0600 file in the app's sandbox container instead. It works the same. |

## Layout

| Folder | Built into | Contents |
| --- | --- | --- |
| `TapoKit/` | app, tests | KLAP handshake, AES-128-CBC session, device-info parsing, commands |
| `Shared/` | app | Settings store, credential store, `LightService`, scenes, error text |
| `TapoControl/` | app | Menu bar UI and `AppIcon.icon` (app icon) |
| `TapoKitTests/` | tests | Vectors generated by `tools/gen_vectors.py` from python-kasa |
| `Config/` | — | Info.plist and entitlements (sandbox, outgoing network) |
| `Design/` | — | Icon artwork: `AppIcon.svg` (flat) and `icon-layers/` (the layers in `AppIcon.icon`) |
| `tools/` | — | `klap_probe.py` (Terminal check, stdlib + macOS `openssl`), `mock_bulb.py` and `gen_vectors.py` (need `pip install python-kasa`) |

The project uses Xcode's folder-synchronized groups, so new `.swift` files dropped into a folder are
picked up automatically.

The app icon is an Icon Composer document, `TapoControl/AppIcon.icon` (layers front to back: bulb +
base, glow, background). macOS 26+ puts icons from a plain asset catalog in a grey frame, so the `.icon`
format is required for the icon to show properly. Open it in Icon Composer (Xcode → Open Developer Tool) to
tweak the Liquid Glass settings. The layer artwork comes from `Design/icon-layers/*.svg`; to change it,
re-render each SVG to a 1024×1024 PNG with the same name in `AppIcon.icon/Assets/`.

## Protocol notes

KLAP works only while **Third-Party Compatibility is on** in the Tapo app. With it off, firmware 1.4.x
bulbs switch to TPAP (SPAKE2+), which this app doesn't implement. Everything protocol-specific sits behind
`TapoLight`/`KlapSession`, so a TPAP or Home Assistant backend can replace it without touching the UI.
